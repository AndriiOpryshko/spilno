# Feature review of 2026-11-10 (stage 17, `/sdlc:review-feature`)

**Verdict:** CHANGES REQUESTED

Reviewed: the net diff of PR #48, `git diff bd78ad7 b3e6b36` (`bd78ad7` is `main` before the merge,
`b3e6b36` the merge commit): 400 files, +37282 / −2122, of which 330 files (+32925 / −2088) are under
`services/`, `apps/`, `tests/` and `infra/`. 55 commits; their `SDLC-AC` trailers claim all 42 ACs of PRD §5.
The feature was already merged when the review ran, so this is a post-merge review and every fix goes on
a new branch off a fresh `main`.

How: five clean-context `sdlc:reviewer` agents (read-only), one per slice: the stage-1 trace of
US-01..US-03, the stage-1 trace of US-04..US-09, stage-1 contract fidelity (data model, OpenAPI, ADR
0001–0009, PRD §10), stage-2 quality of the Go backend, stage-2 quality of the web app. Each re-read the
PRD, SAD, data model, contract, ADRs, test plan and `tasks.json` itself. The orchestrator then read the
cited code for the findings marked «verified» below. Nothing was run: no test suite, no dev server.
Findings not marked «verified» rest on the reviewer's read alone.

Resolution: every finding was put to the product owner (Andrii Opryshko) on 2026-11-10 in four groups;
the answer for all four was **fix now**, including the board-protocol-dependent ACs (F15), which are to
be delivered in this feature rather than de-scoped. No finding was deferred or dismissed.

Paths: `core/` is `services/core/internal/`, `web/` is `apps/web/src/`, `e2e/` is `apps/web/e2e/`.

## What holds

- All nine user stories have at least one AC and a §6 flow; PRD §5 has no AC outside the reviewed set, and
  every AC reaches a task in `tasks.json`.
- All 21 staged migrations are identical to live `00028`–`00048`; columns, indexes, RLS policies and Down
  migrations match `data-model.md`.
- All 35 operations and every component of the contract delta are present in
  `services/core/api/openapi.yaml`; the 17 `identity.*` codes and `governance.drive_not_connected` are each
  defined once with the contract's status.
- ADR 0001, 0002, 0004, 0005, 0008 and 0009 are honoured. ADR-0003 and ADR-0007 are honoured in the main
  path (F16, F17 and F15 name the gaps); ADR-0006 diverges in one case (F05).
- Every allowed and refused transition of PRD §10 has its guard in `core/identity/domain`, apart from F05.
- The backend integration tests of the ACs marked OK assert real outcomes (stored rows, problem codes,
  existence hiding, rollback on a failed step).
